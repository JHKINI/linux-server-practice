# 06. 서버 호스팅 · 실무 유지보수

> 교수님 특강 "실무 유지보수" 필기 정리
> 서버를 빌려서 → 도메인을 연결하고 → 안전하게 운영하기까지의 흐름

## 한눈에 보기

```text
사용자 ──(도메인 입력)──> DNS ──(IP 알려줌)──> 서버(공인 IP)
                                                  │
                                         Nginx / Apache (80, 443)
                                                  │  도메인 이름을 보고 분기
                                    ┌─────────────┴─────────────┐
                              a.aisw.org → :5000          b.aisw.org → :5001
```

## 1. 왜 서버는 리눅스인가

- 윈도우보다 개발 환경을 갖추기 편하다. 패키지 관리자(`apt`, `yum`)로 필요한 것을 바로 설치한다.
- 커널(Kernel)에서 필요 없는 것을 다 빼고 가볍게 운영할 수 있다.
- 실무에서는 **리눅스 + 도커** 환경을 서버로 많이 쓴다.

## 2. 호스팅 종류

| 종류 | 설명 |
|---|---|
| VPS (가상 서버) | 물리 서버 한 대를 여러 가상 서버로 나눠서 빌려 쓰는 방식 |
| 리얼 서버 (서버 호스팅) | 물리 서버 한 대를 통째로 사용. 크기는 1U · 2U · 4U, 임대형 / 소유권 이전형이 있고 14만~20만 원 선 |
| 코로케이션 | 내 서버 장비를 IDC(데이터센터)에 가져다 놓고 회선·전원·공간만 빌리는 방식 |

수업에서는 **카페24 클라우드 V**를 사용했다.

서버를 고를 때 보는 것

- **사양**: CPU, RAM
- **트래픽**: 인바운드(들어오는 것) / 아웃바운드(나가는 것). 내부망 안에서 오가는 트래픽은 과금되지 않는다.

## 3. IP 주소

서버를 임대받으면 가장 중요한 정보가 **IP 주소(또는 엔드포인트 주소)** 다.

| 구분 | 설명 |
|---|---|
| 공인 IP | 전 세계에서 유일한 주소. 인터넷에서 바로 찾아올 수 있다 |
| 사설 IP | 공유기 안쪽 내부망에서만 쓰는 주소 (예: `192.168.x.x`) |
| 고정 IP | 바뀌지 않는 공인 IP |
| 유동 IP | 접속할 때마다 바뀔 수 있는 공인 IP |

### 데이터가 오가는 과정

1. 보낼 때 **목적지 IP + 내 IP + 데이터 + MAC 주소**를 함께 보낸다.
2. 내 PC → 공유기 → L2 / L3 장비 → 공인 IP를 달고 인터넷으로 나간다.
3. 받는 쪽은 "누가 보냈는지" 정보를 함께 받기 때문에 그 주소로 **응답**을 돌려보낸다.

## 4. 도메인과 DNS

- **DNS**는 "이 도메인은 이 IP와 같아요"라는 정보를 가지고 있고, 이 정보는 전 세계에 동일하게 배포된다.
- 도메인(예: `aisw.org`)을 구매하면 **네임서버**에 "이 주소는 이 IP로 연결돼요"라는 정보를 저장한다.
  - 이 작업을 **A 레코드** 등록 또는 **CNAME** 등록이라고 부른다.
  - A 레코드: 도메인 → IP / CNAME: 도메인 → 다른 도메인
- 네임서버의 정보가 DNS로 전달되고, DNS는 그 정보를 클라이언트에게 알려 주는 역할을 한다.

### 서브도메인

```text
aisw.org
www.aisw.org
```

둘은 서로 다른 주소지만 같은 곳으로 연결해 둔다. 점(`.`) 앞에 붙는 부분(`www`, `a`, `b` …)을 **서브도메인**이라고 한다.

### 호스트 변조 (보안 위협)

`naver.com`을 요청했는데 진짜 네이버가 아니라 가짜(피싱) 사이트로 가게 만드는 공격이다. 도메인 → IP 연결 정보가 변조되지 않도록 주의해야 한다.

## 5. 엔드포인트와 포트 연결

- **IP 하나에 도메인 여러 개**를 연결할 수 있다.
- 호스팅 업체는 요청이 어떤 엔드포인트(도메인)로 들어왔는지 보고 해당 고객의 가상 서버로 연결해 준다.

### 리버스 프록시로 포트 숨기기

내 서버에서 서비스 A는 5000번, B는 5001번 포트로 떠 있다면 원래는 `aisw.org:5000`처럼 포트까지 입력해야 접속된다.
80번 포트를 열어 둔 **Nginx(또는 Apache)** 를 앞에 두면 도메인 이름만으로 나눠 줄 수 있다.

| 요청 | 연결되는 곳 |
|---|---|
| `a.aisw.org` | 내부 5000번 포트 |
| `b.aisw.org` | 내부 5001번 포트 |
| 그 외 | 에러 페이지 응답 |

요청에 따라 5000번으로 보내거나, 나중에 다른 곳으로 연결을 바꾸는 것도 가능하다.

```nginx
# 예시: a.aisw.org 로 들어온 요청을 5000번 포트로 넘기기
server {
    listen 80;
    server_name a.aisw.org;

    location / {
        proxy_pass http://127.0.0.1:5000;
    }
}
```

## 6. 포트포워딩과 터널링

### 포트포워딩

공유기 하나에 컴퓨터가 여러 대 있으면, 밖에서 공인 IP로 요청이 와도 **어느 컴퓨터로 보내야 할지 정보가 없다.**
그래서 "80번으로 온 요청은 A 컴퓨터의 80번으로" 같은 규칙을 공유기에 직접 등록해야 한다. → 번거롭다.

### 터널링

- 내부망의 컴퓨터는 원래 **안에서 밖으로 나가는 방향**으로만 길이 열린다.
- 안에서 밖으로 먼저 연결을 걸면 **통로**가 생기는데, 이 통로를 거꾸로 이용해 밖에서 들어오게 하는 것이 터널링이다.
- 이 방식을 쓰면 별도 서버나 포트포워딩 없이도 도메인을 내 컴퓨터에 연결할 수 있다.

```text
사용자 → 도메인 → Cloudflare ══(터널)══> 내부망의 A 컴퓨터
```

| 방법 | 특징 |
|---|---|
| Cloudflare Tunnel | 요즘 가장 편해서 많이 쓰는 방식 |
| SSH 리버스 터널 | SSH로 직접 통로를 만드는 방식 |

## 7. 서버 접속과 보안

서버는 아래 **3가지만 알면 제어할 수 있다.** 그만큼 유출되면 위험하다.

1. IP (엔드포인트)
2. SSH 접속 포트
3. ID / PW

> FTP는 필수가 아니다. SSH만 있으면 파일 전송도 가능하다.

보안 수칙

- **포트는 유지보수가 필요할 때만 열고**, 평소에는 닫아 둔다.
- DB에 저장할 때 **평문으로 저장하지 말고 암호화**해야 한다. (비밀번호 등)

## 8. HTTP · HTTPS · SSL

| 프로토콜 | 포트 | 특징 |
|---|---|---|
| HTTP | 80 | 암호화 없음. POST로 보내도 ID/PW가 패킷에 그대로 보인다 |
| HTTPS | 443 | SSL 인증서로 암호화해서 전송 |

- **SSL 인증서**는 보험 같은 것. 무료 인증서는 **3개월 단위로 갱신**해야 하고, 갱신은 자동화할 수 있다.
- 웹 서버는 **Nginx**를 많이 쓰고 Apache도 쓴다.
- HTTP로 들어온 요청은 **HTTPS로 리다이렉트**해서 보안을 적용하는 경우가 많다.

```nginx
# 예시: http 요청을 https 로 넘기기
server {
    listen 80;
    server_name aisw.org www.aisw.org;
    return 301 https://$host$request_uri;
}
```

## 정리: 서비스 하나를 올릴 때의 순서

1. 서버 임대 (VPS 등) → 공인 IP 받기
2. 도메인 구매 → 네임서버에 A 레코드로 IP 연결
3. SSH로 접속해서 서비스 실행 (예: 5000번 포트)
4. Nginx로 도메인 → 내부 포트 연결
5. SSL 인증서 적용, HTTP → HTTPS 리다이렉트
6. 안 쓰는 포트 닫기, 민감 정보 암호화
